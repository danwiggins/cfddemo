# MethylBERT model bundle contract

The Lab's `methylbert` result needs a **fine-tuned tumour/normal model**. The generic pretrained MethylBERT encoder is not a tumour-purity model. No suitable public checkpoint has been identified. The registered algorithm therefore skips unless an operator supplies a trusted bundle and the pinned installed-code digest, and the host has a usable CUDA GPU.

An operator-trusted, uncompressed TAR contains exactly these seven regular files, with no links, PAX/GNU extensions, or extra members. The archive and sum of member sizes are each capped at 2 GiB:

```text
bundle.json
bert.model/config.json
bert.model/pytorch_model.bin
bert.model/dmr_encoder.pickle
bert.model/read_classification_model.pickle
train_seq.csv
dmrs.tsv
```

After creating `bundle.json` with the six exact file hashes, run this from the directory containing those paths (GNU tar, default blocking factor):

```sh
tar --format=ustar -cf model.tar bundle.json bert.model/config.json bert.model/pytorch_model.bin bert.model/dmr_encoder.pickle bert.model/read_classification_model.pickle train_seq.csv dmrs.tsv
```

List the member paths explicitly: a leading `./`, directory entries, PAX/GNU headers, or nondefault TAR record padding is refused. Every listed file must be nonempty.

`bundle.json` has schema `traceback.methylbert-bundle.v1`, a `model_id`, a 40-character upstream Git commit, a human-readable `source` and `terms` statement, a reference SHA-256, `n_mers` of 3, a positive `seq_len` no greater than 4096, and a `files` object with the SHA-256 of each of the six non-manifest files. Registration checks the commit and reference fields for valid shape; the runtime readiness check later requires the pinned upstream commit and the selected input reference. Registration refuses missing, extra, duplicate, linked, oversized, or digest-mismatched members. The model and training table must be the matched fine-tuning pair; the training table supplies class margins during deconvolution.

Register through the Lab-owned asset command: `traceback lab asset add methylbert-bundle --root ROOT --file model.tar --source-label SOURCE --terms restricted`. Registration validates the TAR, records its exact SHA-256, and stores a private copy under `ROOT/lab/assets/methylbert-bundle/<sha256>/`. The Lab API refuses replacement at that digest; it does not cryptographically authenticate operator-supplied source or terms metadata against a local administrator who can edit storage. Inspect a registration with `traceback lab asset inspect methylbert-bundle --root ROOT --sha256 SHA256`. Different model revisions have different digest directories. The Lab worker reverifies the registration, copies its exact bytes to private scratch, and unpacks it before loading. The two pickle files can execute code when loaded: accept bundles only from an operator-trusted source and never load them during registration or in the web process.

The runtime contract refuses a model or installed package outside pinned commit `f82f83b0bc20e2af1441795536ec9f338fbbb3e7`, a mismatch against an operator-trusted installed-code SHA-256, a mismatched reference, non-ONT input, fewer than 2.5 million eligible reads, or an unavailable CUDA GPU. The code digest covers installed MethylBERT `.py` files listed in the distribution RECORD; it does not cover bytecode caches, compiled extensions, or unlisted files. The operator must establish the expected digest from a trusted installation. Its standalone worker helper has a two-hour deadline and bounded logs; only a small, strict tumour/normal aggregate with a classified-read count meeting the operator-supplied support floor and no larger than the eligible-read count may be accepted from private scratch. Eligible input reads and classified reads are different denominators. The Lab has no qualified minimum classified count or model reliability rule; the operator must independently establish the model-specific floor and supply it explicitly. A positive result remains exploratory and carries its actual classified-read denominator, even when it meets that floor.

Run a registered model with `traceback lab run INPUT --only methylbert --reference REFERENCE_ID --methylbert-bundle-sha256 BUNDLE_SHA256 --methylbert-code-sha256 INSTALLED_CODE_SHA256 --methylbert-min-classified QUALIFIED_COUNT`. The input must have ONT read groups, a single header-declared modified-base model, eligible MM/Mm-tagged reads, the exact reference registered with the bundle, and at least 2.5 million D21-eligible reads. The Lab measures eligibility from its read summary and copies only those selected BAM records into a private indexed BAM before upstream Dorado MM/ML preprocessing. For a downsample or split half the same read-name mask is applied; the 2.5-million floor is reevaluated on that derived input. Untagged eligible reads may be present; upstream discards those without usable methylation calls, and the classified count is checked separately. Skips are recorded when any prerequisite is absent.

The Lab's execution identity pins the bundle and installed-code digests, the reference, tokenizer settings through the bundle digest, the header-declared basecalling model, the operator's support floor, the digests of the child script and its runtime/GPU-probe helpers, Python and numerical package versions, and, when a model is configured, the count and ordered names/capabilities of all visible CUDA devices plus Torch CUDA/cuDNN versions and precision flags. The parent gathers GPU details in a bounded, short-lived process so it does not retain a CUDA context during inference. The child restores the selected precision flags after importing the model package and rechecks this runtime identity before model loading and the parent publishes it in provenance. The inner child runs with Python isolated mode, a private bytecode cache, model-hub offline flags, an allowlisted environment, a single preprocessing/tokenization worker and zero data-loader workers. These flags are not an operating-system network sandbox and do not attest native library bytes or guarantee identical numerical results across GPUs. The child rechecks the pinned installed sources and import location before model loading. The bundle contains the registered training table, not upstream's `train_param.txt`; the child computes exact N/T class margins from that copied table, requires tumour-specific dense DMR labels, and sizes the model from the full DMR table before loading. It checks classifier probabilities and the tumour/normal mapping before deconvolution. The verified pickle files are placed where the pinned trainer expects them. It never invokes upstream's CLI, which hardcodes 40 data-loader workers. The parent accepts only the strict aggregate and publishes a small provenance file; per-read data and logits stay in private scratch. The inner child has its own process-group timeout; the outer Lab worker kills escaped descendant groups on interruption, and the attempt scratch is removed after success or failure.

These mechanics have focused tests, but no real tumour/normal checkpoint, complete ONT input-path replay, GPU execution, independently established classified-support floor, or biological recovery evidence has been supplied. The Lab must not portray this result as clinically qualified.

Before a result can be treated as biologically validated, an independently trusted tumour/normal checkpoint must be checked on complete ONT input with the matching reference and basecalling model. Its classified-read support, calibration, and recovery against independent truth must be qualified. The Lab's current result is deliberately `SPECULATIVE`; neither the 2.5-million eligible-read floor nor a positive classified count establishes that qualification.

Upstream references: [MethylBERT source](https://github.com/CompEpigen/methylbert), [data preparation](https://methylbert.readthedocs.io/en/latest/tutorials/01_Data_Preparation.html), and [tumour deconvolution](https://methylbert.readthedocs.io/en/latest/tutorials/05_tumour_deconvolution.html). The hosted 2.0.2 data guide still describes Bismark/XM input, while current source includes Dorado MM/ML support. A pinned-source smoke of the Dorado parser (`src/methylbert/data/bam.py`, SHA-256 `c5b30a5c6dfdd64cf30241a18d193388924c82b670f0a2d82e893f2c7e71c6fe`) decoded a forward read and the repository's modkit-validated synthetic reverse fixture. This verifies the parser on those cases, not a complete ONT BAM or tumour model.
